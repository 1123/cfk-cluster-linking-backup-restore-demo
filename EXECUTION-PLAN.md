# Demo – Cluster Linking Backup & Restore on GKE

**Execution plan / runbook – v2.2 (incorporates `comments.txt` + review comments 2) – FOR REVIEW**
Source: architecture diagram (kept locally, not in the repository)

---

## 0. Goal & scope

Demonstrate that a Confluent Platform (CP) cluster that **crashes hard and is completely lost** (data loss,
broken configuration, ransomware) can be restored from a second cluster via **Cluster Linking**:

| Step | Diagram | What happens |
|------|---------|--------------|
| A | Setup Cluster Link | Link `pri-to-sec` created **on Secondary** (destination-initiated), pulling from Primary |
| B | Establish Mirror Topics | `t1..t3` on Secondary become read-only mirrors of Primary `t1..t3` (+ consumer offset sync) |
| C | Start Producers / Consumers | Sequenced Java test traffic on Primary; continuous verification |
| D | Delete Primary Cluster | **Hard crash while producers & consumers are running**; Kafka + KRaft + PVCs wiped. Secondary mirrors are **failed over** (frozen, authoritative copy) |
| E | Recreate empty Primary | Same service names, new cluster ID, **no topics** |
| F | Reverse Cluster Link | Link `sec-to-pri` created **on Primary**, mirrors `t1..t3` back incl. consumer offsets, then **promoted**; producers resume by themselves, consumers are restarted |
| G | Re-protect | Re-establish `pri-to-sec` so the setup is DR-protected again |

Cross-cutting requirements from the diagram:
- **OAuth** with a **central IdP** → **Keycloak** (OIDC client-credentials flow).
- **TLS** for all Kafka traffic (client↔broker, broker↔broker, broker↔controller, cluster link, Admin REST) and to the IdP.
- **Confluent for Kubernetes (CFK)** manages Kafka, KRaft, topics, cluster links and mirror topics declaratively.

Out of scope: automatic client failover (needs Confluent Gateway – see sticky note), Kafka ACLs, Schema Registry,
Control Center, production hardening (HA Keycloak, Vault, GitOps, multi-region).

## 1. Target architecture

```
 GCP project <gcp-project> · europe-west3 (Frankfurt) · ONE regional GKE cluster "cl-backup-restore" (zones a/b/c)
 ┌──────────────────────────────────────────────────────────────────────────────────────────────────────────┐
 │ node pool default (system)        node pool kafka (role=kafka)            node pool clients (role=client) │
 │                                                                                                          │
 │ ns confluent-operator : CFK 3.4.0 (watches kafka-primary, kafka-secondary)                                │
 │ ns keycloak           : Keycloak 26 + Postgres (CNPG)   https://keycloak-service.keycloak.svc.cluster.local:8443 │
 │ ns kafka-primary      : 3x KRaft, 3x broker, KafkaRestClass, KafkaTopics t1..t3, (F) ClusterLink sec-to-pri │
 │ ns kafka-secondary    : 3x KRaft, 3x broker, KafkaRestClass, (A) ClusterLink pri-to-sec                   │
 │ ns demo-clients       : Java producers / consumers / audit job, PVC "evidence"                            │
 └──────────────────────────────────────────────────────────────────────────────────────────────────────────┘
 Client + link endpoint:  kafka.kafka-primary.svc.cluster.local:9094    kafka.kafka-secondary.svc.cluster.local:9094
```

Design decisions:

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | **One regional GKE cluster**, namespaces per role (per review comment) | Simplest setup. "Primary lost" = Kafka + KRaft CRs, topics, PVCs and disks in `kafka-primary` are destroyed (namespace itself stays); Keycloak and clients are unaffected. |
| D2 | **europe-west3 (Frankfurt)**, 3 zones | Per review comment; brokers spread across zones. |
| D3 | GKE created like `gcp-cp-200MB-per-sec-load-test/scripts/01-create-cluster.sh` (system + `kafka` + `clients` node pools) **plus `--enable-dataplane-v2`** | Reuse proven script; Dataplane V2 enforces NetworkPolicies (used for a deterministic hard crash in D). |
| D4 | **No ExternalDNS / LBs / Cloud DNS** – Kubernetes service DNS only | Everything in one cluster (per review comment). Service names survive re-creation → clients need **no config change** after restore. |
| D5 | **Keycloak 26.x** via official Keycloak Operator + `KeycloakRealmImport`, Postgres via **CloudNativePG** | Confirmed by review. Declarative realm; no Bitnami (image licensing change 2025). |
| D6 | **One demo CA**; CFK `autoGeneratedCerts: true` in both Kafka namespaces using the **same CA** | Both clusters, link, Keycloak and clients trust one `ca.pem`. Auto-generated certs include `*.kafka.<ns>.svc.cluster.local` SANs. |
| D7 | Listeners: **internal + replication + controller = mTLS**; additional **custom listener `oauth` (9094) = SASL_SSL/OAUTHBEARER** for clients and cluster link | Kafka control plane and CFK do not depend on the IdP; OAuth where the diagram asks for it. |
| D8 | Cluster links **destination-initiated**, source referenced by **explicit `clusterID`** | No dependency on the source cluster's REST class – important because the source cluster disappears in D. |
| D9 | **CFK 3.4.0** (Helm chart `0.2038.1`), **CP 8.4.x** (KRaft only) | Confirmed by review. Pin exact CP patch at execution time. |
| D10 | **Java 21 clients**, plain `kafka-clients` (CP 8.4 `-ccs` version), one fat-jar image with modes `producer` / `consumer` / `audit` | Per review comment; no framework overhead, behaviour fully visible. |
| D11 | Topics `t1`, `t2`, `t3` – 6 partitions, RF 3, `min.insync.replicas=2` | Matches diagram (`t1 … tn`). |
| D12 | **Producers run during the whole incident; consumers are stopped after the crash and restarted after the restore** | Agreed. Producers recover on their own once topics are writable; consumers must be inactive so their offsets can be restored by the link. |

## 3. Phase 0 – GKE cluster

### 0.1 `scripts/01-create-cluster.sh` (adapted from the load-test repo)
```bash
#!/usr/bin/env bash
set -euo pipefail
source "$(dirname "$0")/../00-env.sh"
ZONES=${REGION}-a,${REGION}-b,${REGION}-c
gcloud config set project "$PROJECT"
gcloud services enable container.googleapis.com artifactregistry.googleapis.com

gcloud container clusters create "$CLUSTER" --region "$REGION" --node-locations "$ZONES" \
  --num-nodes 1 --machine-type n2-standard-4 --disk-size 50 \
  --enable-dataplane-v2 \
  --labels "$LABELS" --release-channel regular --quiet

gcloud container node-pools create kafka --cluster "$CLUSTER" --region "$REGION" --node-locations "$ZONES" \
  --num-nodes 1 --machine-type n2-standard-8 --disk-type pd-ssd --disk-size 100 \
  --node-labels role=kafka --node-taints dedicated=kafka:NoSchedule --quiet

gcloud container node-pools create clients --cluster "$CLUSTER" --region "$REGION" --node-locations "$ZONES" \
  --num-nodes 1 --machine-type n2-standard-4 --node-labels role=client --quiet

gcloud container clusters get-credentials "$CLUSTER" --region "$REGION"
gcloud artifacts repositories create demo --repository-format=docker --location="$REGION" --labels "$LABELS" || true
kubectl apply -f k8s/storageclass.yaml
for ns in confluent-operator $NS_PRI $NS_SEC $NS_KC $NS_CLI; do kubectl create ns $ns --dry-run=client -o yaml | kubectl apply -f -; done
```
Kafka pool sizing: per zone 1× n2-standard-8 hosts 1 broker + 1 controller **of each** cluster
(brokers 2 vCPU / 8 GiB, controllers 0.5 vCPU / 2 GiB → ~5 vCPU / 20 GiB per node).
The pool is tainted `dedicated=kafka:NoSchedule`; Kafka and KRaftController CRs get `podTemplate.tolerations` +
`nodeSelector role=kafka`, so Keycloak/operators/clients cannot eat the reserved capacity.
Dry-run check: the labels CFK puts on the pods match the `topologySpreadConstraints` selector (`kubectl get pod -o wide` → one broker + one controller per cluster per zone).

`k8s/storageclass.yaml`:
```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata: { name: kafka-ssd }
provisioner: pd.csi.storage.gke.io
parameters: { type: pd-ssd }
reclaimPolicy: Delete            # deleting PVCs really deletes the data (phase D)
volumeBindingMode: WaitForFirstConsumer
allowVolumeExpansion: true
```

**✅ Gate 0:** 9 nodes Ready (3 per pool, one per zone); `kubectl get ns` shows the 5 namespaces;
`kubectl -n kube-system get pods -l k8s-app=cilium` running (Dataplane V2).

## 7. Phase 4 – Java demo clients (`clients/`, `scripts/05-clients.sh`, ns `demo-clients`)

### 4.1 Client configuration (ConfigMap + Secret)
```properties
bootstrap.servers=kafka.kafka-primary.svc.cluster.local:9094
security.protocol=SASL_SSL
sasl.mechanism=OAUTHBEARER
sasl.login.callback.handler.class=org.apache.kafka.common.security.oauthbearer.OAuthBearerLoginCallbackHandler
sasl.oauthbearer.token.endpoint.url=${KC_TOKEN_URL}
sasl.jaas.config=org.apache.kafka.common.security.oauthbearer.OAuthBearerLoginModule required clientId="${CLIENT_ID}" clientSecret="${CLIENT_SECRET}";
ssl.truststore.type=PEM
ssl.truststore.location=/etc/demo-ca/ca.pem
metadata.recovery.strategy=rebootstrap
```
JVM flags: `-Djavax.net.ssl.trustStore=/truststore/ca.p12` (built by `keytool` init container – token endpoint is HTTPS),
`-Dorg.apache.kafka.sasl.oauthbearer.allowed.urls=${KC_TOKEN_URL}`.

**Evidence storage (decided):** two locations, never mixed:
- **Client evidence** (producer/consumer/audit logs) → PVC `evidence` (RWO, pd-ssd). All `demo-clients` pods are pinned to **one node**
  (`nodeSelector: role=client, topology.kubernetes.io/zone=europe-west3-a`); RWO allows multiple pods on the same node.
  A long-running `evidence-shell` pod (busybox, same PVC) is used for inspection and `scripts/rpo.sh`.
  Writers flush after every line (`BufferedWriter.flush()`), so a pod kill loses nothing that was logged.
- **Operator-side evidence** (timeline, `kubectl`/group-offset outputs, CR dumps) → local directory `./evidence/` on the operator's laptop.
- End of demo: `kubectl -n demo-clients cp evidence-shell:/evidence ./evidence/clients`.

### 4.2 Applications (one image, `java -jar demo.jar <mode>`)
- **Producer** (Deployment per topic, `run_id` = pod start UUID): 20 msg/s, `acks=all`, `enable.idempotence=true`,
  `delivery.timeout.ms=30000`, `max.block.ms=10000`. Value JSON `{run_id, topic, seq, ts, payload}`, key `seq % 12`, header `run_id`.
  Every delivery callback appends `(ts, topic, seq, partition, offset, status)` to `/evidence/producer-<topic>.log`
  (`status` = `ACKED` or `FAILED:<exception>`). Resilience required for D–F:
  - catch every `send()`/callback exception, log it, continue with next `seq` (failed seqs are *never acked → not data loss*);
  - **callbacks only log and set a flag** – never close/re-create the producer inside a callback (runs on the I/O thread → deadlock);
  - a **supervisor loop in the main thread** replaces the `KafkaProducer` instance (close with timeout 0, build new) when
    (a) a callback flagged a fatal/idempotence error (`OutOfOrderSequenceException`, `UnknownProducerIdException`,
    `InvalidProducerEpochException`, `ProducerFencedException`, `IllegalStateException`/`KafkaException` from a closed producer), or
    (b) an `AdminClient` (`describeCluster().clusterId()`, polled every 5 s) reports a **cluster-ID change** – broker IDs and hostnames
    are reused by the recreated primary, so the client may reconnect transparently without any error;
  - retry producer construction in a loop if bootstrap DNS is temporarily unresolvable;
  - log every replacement as `PRODUCER_RECREATED reason=… old_cluster=… new_cluster=…`.
  Dry-run assertion: the JVM process (pod restart count 0) stays the same, the producer instance changes, and `ACKED` resumes after promote.
- **Consumer** (Deployment per topic, group `demo-cg-<topic>`): manual commit every 1 s, `auto.offset.reset=earliest`.
  Persists per partition `last_processed_offset` to `/evidence/consumer-<topic>.json`; at startup logs the assigned start offset per partition
  and computes `reprocessed = max(0, last_processed+1 − start)` and `skipped = max(0, start − (last_processed+1))`.
  In-run gap/duplicate detection per `run_id`.
- **Audit** (Job, `--bootstrap pri|sec --label X`): manual assignment, reads `t1..t3` per partition from start to end offset;
  writes `/evidence/audit-X.json`: per partition start/end offset, count, per-`run_id` min/max seq & missing ranges, and a
  **SHA-256 over canonical records** `(offset, timestamp, key, sorted headers, raw value)`.
- **`scripts/rpo.sh`**: per partition, records with `status=ACKED` and `offset ≥ secondary end offset` = **lost** (offsets are preserved by Cluster Linking) → count + time window.

### 4.3 Build & deploy
```bash
scripts/build-image.sh                      # Jib build + push of $IMAGE
kubectl apply -f k8s/clients/   # config, evidence PVC, deployments with replicas: 0 (nodeSelector role=client)
```

## 8. Phase 5 – Demo runbook (A → G)

> Every step: **Action → Verify → Expected**. Timeline in local `evidence/timeline.txt` (`date -u` at each step) for RPO/RTO.

### Preparation – topics on Primary
`kubectl apply -f k8s/kafka-primary-topics/topics.yaml` (KafkaTopic `t1..t3`, 6p, RF 3) → all `CREATED`.

### A – Cluster link `pri-to-sec` (ns `kafka-secondary`)
```yaml
apiVersion: platform.confluent.io/v1beta1
kind: ClusterLink
metadata: { name: pri-to-sec, namespace: kafka-secondary }
spec:
  name: pri-to-sec
  destinationKafkaCluster: { kafkaRestClassRef: { name: kafka-rest } }
  sourceKafkaCluster:
    bootstrapEndpoint: kafka.kafka-primary.svc.cluster.local:9094
    clusterID: ${PRI_CLUSTER_ID}
    authentication:
      type: oauth
      jaasConfig: { secretRef: oauth-jaas-cluster-link }
      oauthSettings:
        tokenEndpointUri: https://keycloak-service.keycloak.svc.cluster.local:8443/realms/kafka-demo/protocol/openid-connect/token
    tls: { enabled: true, secretRef: demo-ca-pem }
  consumerGroupFilters:
    - { name: "demo-cg-", patternType: PREFIXED, filterType: INCLUDE }
  configs:
    consumer.offset.sync.enable: "true"
    consumer.offset.sync.ms: "5000"
    topic.config.sync.ms: "5000"
  mirrorTopics: []        # step B
```
Verify: `kubectl -n kafka-secondary get clusterlink pri-to-sec -o yaml` → created, `sourceKafkaClusterID == PRI_CLUSTER_ID`, no errors.

### B – Mirror topics
Add `mirrorTopics: [ {name: t1}, {name: t2}, {name: t3} ]`, re-apply.
Verify: all mirrors `ACTIVE`; producing to secondary `t1` is rejected (read-only mirror).

### C – Start producers and consumers (against Primary)
```bash
kubectl -n demo-clients scale deploy -l app=producer --replicas=1
kubectl -n demo-clients scale deploy -l app=consumer --replicas=1
```
Run ≥ 10 min. Verify:
1. Consumers: no gaps/duplicates; producers: only `ACKED`.
2. `scripts/link-status.sh pri-to-sec` → mirror lag per partition ≈ 0.
3. `scripts/end-offsets.sh` – high watermarks on secondary trail primary by ≤ a few records.
4. `scripts/group-offsets.sh sec` – `demo-cg-*` offsets present on secondary, ≤ ~5 s behind.
5. Config sync: change `retention.ms` of `t1` on primary → visible on secondary mirror within 5 s.
6. Token refresh: > 5 min (token TTL 300 s) without auth errors.
7. `audit --bootstrap pri --label pri-before`.

### D – Hard crash of the Primary cluster (producers + consumers running)
**D.0 Baseline** (seconds before the crash): `scripts/group-offsets.sh pri > evidence/groups-pri-before.txt`,
`scripts/group-offsets.sh sec > evidence/groups-sec-before.txt`.

**D.1 Crash** – deterministic "lights out" (no graceful shutdown that would let replication drain):
```bash
date -u +"D-start %FT%TZ" | tee -a evidence/timeline.txt
kubectl apply -f k8s/netpol-isolate-primary.yaml                      # deny-all ingress+egress in kafka-primary
kubectl -n kafka-primary delete pod --all --grace-period=0 --force
```
Expected immediately: producers log `FAILED:` deliveries / timeouts (and keep running), consumers stall,
link `pri-to-sec` reports source unavailable; data on secondary still readable.

**D.2 Incident response – stop consumers** (they must be inactive for offset restore, D12):
`kubectl -n demo-clients scale deploy -l app=consumer --replicas=0`. Producers stay up.

**D.3 Destroy the Primary cluster** – data really gone; the **namespace `kafka-primary` stays** (secrets, KafkaRestClass,
CFK RBAC and generated certs are kept):
```bash
# 1. Topic CRs first – otherwise CFK would re-create t1..t3 as *regular* topics on the new cluster in E,
#    which blocks creating mirror topics t1..t3 in F. CFK cannot reach the dead brokers → finalizers may need removal.
kubectl -n kafka-primary delete kafkatopic --all --wait=false
sleep 30; for t in $(kubectl -n kafka-primary get kafkatopic -o name); do
  kubectl -n kafka-primary patch $t --type=merge -p '{"metadata":{"finalizers":[]}}'; done
# 2. Cluster CRs (StatefulSets, pods, services go with them)
kubectl -n kafka-primary delete kafka/kafka kraftcontroller/kraftcontroller --wait=true --timeout=5m
# 3. Storage – CFK sets PV reclaimPolicy to Retain, so delete PVCs and the released PVs explicitly
PVS=$(kubectl get pv -o json | jq -r '.items[] | select(.spec.claimRef.namespace=="kafka-primary") | .metadata.name')
kubectl -n kafka-primary delete pvc --all --wait=true
for pv in $PVS; do kubectl patch pv $pv -p '{"spec":{"persistentVolumeReclaimPolicy":"Delete"}}'; kubectl delete pv $pv --wait=false; done
```
If a CR hangs in deletion: `kubectl patch <cr> --type=merge -p '{"metadata":{"finalizers":[]}}'` (exercise in the dry run **with deny-all active**).
Verify: `kubectl -n kafka-primary get kafka,kraftcontroller,kafkatopic,pvc,pod` empty;
`kubectl get pv -o json | jq '[.items[]|select(.spec.claimRef.namespace=="kafka-primary")]|length'` = 0;
`gcloud compute disks list --filter="labels.goog-k8s-cluster-name=$CLUSTER"` shows only secondary (and Keycloak/evidence) disks.

**D.4 Secure the backup copy (ns `kafka-secondary`):**
1. Save evidence: `kubectl -n kafka-secondary get clusterlink pri-to-sec -o yaml > evidence/pri-to-sec-final.yaml`.
2. Set `state: FAILOVER` for `t1..t3` and apply (failover works without the source; promote would not).
   Verify mirrors `STOPPED`, topics writable, CFK created KafkaTopic CRs `clink-t1-<uid>` …
3. Delete ClusterLink `pri-to-sec` (the old link must never talk to the recreated primary).
4. `audit --bootstrap sec --label sec-after-D`.
5. `scripts/rpo.sh` → **RPO** (acked-but-not-mirrored records per partition + time window).
   Offset RPO = `groups-pri-before` vs `groups-sec-before`.
   Integrity: for each partition, records `< pri-before end offset` in `sec-after-D` match `pri-before`.

### E – Recreate empty Primary
```bash
kubectl delete -f k8s/netpol-isolate-primary.yaml             # lift the "lights out" isolation
kubectl apply -f k8s/kafka-primary/                            # kraft, kafka (restclass unchanged) – NOT kafka-primary-topics/
```
Secrets (CA, OAuth client secrets, password encoder) still exist in the namespace and are reused unchanged.
Verify: Kafka `RUNNING`; new PVCs `Bound` to **new** PVs (none of the D.3 PV names);
new `PRI2_CLUSTER_ID ≠ PRI_CLUSTER_ID`; topic list contains **no `t1..t3`**; no consumer groups.
Producers: reconnect, get `UNKNOWN_TOPIC_OR_PARTITION`/`max.block.ms` timeouts → `FAILED:` entries; **no topic is auto-created**.

### F – Reverse cluster link `sec-to-pri` (ns `kafka-primary`) and restore
```yaml
apiVersion: platform.confluent.io/v1beta1
kind: ClusterLink
metadata: { name: sec-to-pri, namespace: kafka-primary }
spec:
  name: sec-to-pri
  destinationKafkaCluster: { kafkaRestClassRef: { name: kafka-rest } }
  sourceKafkaCluster:
    bootstrapEndpoint: kafka.kafka-secondary.svc.cluster.local:9094
    clusterID: ${SEC_CLUSTER_ID}
    authentication:
      type: oauth
      jaasConfig: { secretRef: oauth-jaas-cluster-link }
      oauthSettings: { tokenEndpointUri: https://keycloak-service.keycloak.svc.cluster.local:8443/realms/kafka-demo/protocol/openid-connect/token }
    tls: { enabled: true, secretRef: demo-ca-pem }
  consumerGroupFilters:
    - { name: "demo-cg-", patternType: PREFIXED, filterType: INCLUDE }
  configs:
    consumer.offset.sync.enable: "true"
    consumer.offset.sync.ms: "5000"
  mirrorTopics: [ { name: t1 }, { name: t2 }, { name: t3 } ]
```
1. Apply; mirrors `ACTIVE`. Producers now get "read-only mirror topic" errors → still `FAILED:` (expected, nothing written).
2. `scripts/wait-lag-zero.sh sec-to-pri` and `scripts/wait-offsets-synced.sh sec-to-pri` (`demo-cg-*` equal on both sides – lag 0 alone does not imply synced offsets).
3. `audit --bootstrap pri --label pri-restored`; `scripts/compare-audits.sh sec-after-D pri-restored` → **identical** offsets, counts and per-partition digests.
4. Set `state: PROMOTE` for `t1..t3`, apply. Verify mirrors `STOPPED`, KafkaTopic CRs `clink-t*-<uid>` on primary.
5. **Producers resume automatically** (first `ACKED` entries after promote; if a producer hit a fatal idempotence error it re-created itself).
6. Restart consumers: `kubectl -n demo-clients scale deploy -l app=consumer --replicas=1`.
   Verify: start offsets = last **synchronized** group offsets; `skipped == 0`; `reprocessed` ≈ offset-sync window (≤ ~5 s × 20 msg/s per topic);
   consumers then read new producer data without gaps.
7. `date -u +"F-done %FT%TZ"` → **RTO** = F-done − D-start; producer outage window = first `FAILED` → first `ACKED` after promote.

### G – Re-protect
1. Delete reverse link `sec-to-pri` (topics already promoted).
2. On secondary delete the failed-over topics (`clink-t*` KafkaTopic CRs) – a regular topic cannot become a mirror.
3. Re-apply `pri-to-sec` with `clusterID: ${PRI2_CLUSTER_ID}` and mirrors `t1..t3` → full re-copy, offsets preserved.
4. Verify as in A–C (lag ≈ 0, offsets synced) → protected steady state again.

*Production note:* CFK ≥ 3.2 supports **bidirectional** links (`linkMode: Bidirectional`) enabling
`reverse-and-start` / `truncate-and-restore` for planned failback without full re-copy.

## 11. Risks & caveats

| # | Topic | Mitigation |
|---|-------|------------|
| R1 | **Cluster Linking is replication, not an immutable backup** | Malicious *config* changes on primary (e.g. `retention.ms=1`) can be synced to mirrors. Known to the customer; **not shown in the demo**. Production: restrict synced configs, lock down link principal, additional immutable backup (e.g. GCS with retention lock). |
| R2 | Broker → Keycloak TLS trust | JVM truststore override (CFK-documented workaround). |
| R3 | `org.apache.kafka.sasl.oauthbearer.allowed.urls` (Kafka 4.x) | Set for brokers and Java clients; verify whether CFK sets it for brokers. |
| R4 | Custom listener naming/advertised addresses | Gate 3 check; fallback: use `internal` listener with OAuth (as in Confluent's OAuth example) and let CFK use mTLS-free REST auth. |
| R5 | Running producers could create regular topics on the new primary | `auto.create.topics.enable=false`; topics manifest kept separate and not applied in E. |
| R6 | Offset sync only for groups **inactive** on destination | Consumers scaled to 0 in D.2, restarted after promote (F.6). |
| R7 | Idempotent producer after cluster replacement | Producer re-creates itself on fatal errors (Phase 4 requirement); verify in dry run. |
| R8 | Embedded Admin REST auth field names | `kubectl explain kafka.spec.services.restProxy` against CFK 3.4. |
| R9 | CFK deletes mirror topics created outside CFK | Manage mirrors only via ClusterLink CR. |
| R10 | CRs stuck in deletion (CFK cannot reach dead brokers) / stale KafkaTopic CRs re-creating `t1..t3` / retained PVs | D.3 deletes KafkaTopic CRs first, finalizer fallback, explicit PV deletion + disk check; rehearsed in dry run. |
| R11 | Single GKE cluster = shared failure domain | Accepted for the demo; "cluster lost" is simulated by deleting the CP cluster and its storage. Production: separate clusters/regions. |
| R12 | Evidence PVC is RWO | All `demo-clients` pods pinned to one node/zone (§4.2); operator-side evidence kept locally. |
| R13 | Keycloak is a SPOF for new connections/token refresh | Fine for demo. |
